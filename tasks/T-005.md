# T-005：事件合约交易（5 端點）

> 难度 ⭐⭐⭐ · OKX 主站事件合约 · 标准 API Key · 约 150 行代码

## 背景

OKX 主站的事件合约（Event Contract）与 Outcomes 独立平台是两套体系。

- 事件合约在 OKX 主站内，instType=EVENTS
- 交易需传 `outcome=yes/no` **+** `speedBump=1`
- 复用标准下单/撤单端点，但多两个必填参数

## API 端点

Base: `https://www.okx.com` · 鉴权: **OKX API Key**

| # | 端点 | 方法 | 说明 |
|---|------|------|------|
| 1 | `POST /api/v5/trade/order` | POST | 下单（需 outcome + speedBump） |
| 2 | `POST /api/v5/trade/cancel-order` | POST | 撤单 |
| 3 | `POST /api/v5/trade/amend-order` | POST | 改单 |
| 4 | `GET /api/v5/trade/fills` | GET | 成交记录 |
| 5 | `GET /api/v5/account/instruments?instType=EVENTS` | GET | 可交易事件合约 |

## 工具规划

| 工具名 | 端点 | 参数 | 鉴权 |
|--------|------|------|:--:|
| `okx_event_place_order` | POST /trade/order | instId, side, sz, outcome, px?, ordType? | 🔐 |
| `okx_event_cancel_order` | POST /trade/cancel-order | instId?, ordId? | 🔐 |
| `okx_event_amend_order` | POST /trade/amend-order | instId?, ordId?, newSz?, newPx? | 🔐 |
| `okx_event_fills` | GET /trade/fills | instId?, limit? | 🔐 |
| `okx_event_instruments` | GET /account/instruments | seriesId? | 🔐 |

## 实现要点

1. **关键参数**：
   - `outcome`: `"yes"` 或 `"no"`（必填）
   - `speedBump`: 非 post_only 订单必须为 `"1"`
   - `instType`: 自动设为 `"EVENTS"`
2. 下单/撤单可以复用 `privateApi.placeOrder()` 等方法，但要加 `outcome` 和 `speedBump` 字段
3. 如果 `privateApi` 已有 `placeOrder`/`cancelOrder`，只需在工具层加参数校验然后透传
4. instruments 查询传 `instType: "EVENTS"`
